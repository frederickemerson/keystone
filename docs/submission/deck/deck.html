The real-world problem

The judgement that keeps a building safe is in a few heads, and those heads are leaving.

1

Concentrated

Keppel’s own brief: critical knowledge sits with a few experts; new staff need a long time to build it.

2

Never written down

The useful part is tacit: when to break the rule, and why.

  • “Always isolate the riser” vs “isolate the sub-valve” — both true, under different conditions.
  • SOPs record the step, not the judgement.

Lost at retirement

  • The knowledge leaves with the person.

The reusable unit

An Intelligence Pill is plain text the organisation owns.

What is in the package

pills/technical-services/chilled-water-leak/

SKILL.mdOwner, steward, approver, version, access and boundaries — plus the prose an LLM host reads.
rules.yaml13 rules: structured triggers, required evidence, action class, forbidden actions, escalation target, deadline, asset overrides.
evidence.yamlThe shared vocabulary — one contract both the pill and the app are tested against.
provenance.jsonEvery rule mapped to the expert’s quote, timestamp and confirmation.
evals/Six past incidents a new version must still agree with.
CHANGELOG.mdAppend-only history.

Why plain text matters

  • Portable. Copied unchanged into .codebuddy/skills/, CodeBuddy reached the same TS-07 decision as our engine — blocked, escalate to the duty LEW, quoting the Chief Engineer. Verified, not claimed.
  • Reviewable. A rule change is a diff an engineer can read.
  • Model-independent. The decision path takes no model input, so swapping the model cannot change a safety outcome.
  • Yours. It is a folder in your repository, not rows in a vendor’s database.

The gate, in one line

Status precedence is fixed code:

not_applicable → blocked → escalate → needs approval → allowed

  • Evidence counts only when it is confirmed and exactly true.
  • An exception may add a requirement. It can never relax a gate.
  • No AI proposal ever executes. Each is held for a named human.
Two pills, one incident

A second pill — tenant-experience/incident-comms — runs beside it during the same leak: it drafts the tenant notice under its own hard rules while Technical Services works the gate.

Pills live in the repository at pills/<domain>/<name>/ — reviewable as a diff5 / 8

Technical architecture

A deterministic core, with the model kept outside it.

Surfaces

Next.js 15 App Router · React 19 · TypeScript · Tailwind v4 · Vercel

  • Teach a skill · Expert call · Decision Canvas
  • Incident Room · Registry · Approvals · Learning
  • Frontline capture from a gate block, job close-out or a QR label on the plant

lib/engine

Pure TypeScript. No LLM, no eval(), no string expressions.

  • Structured conditions: eq, neq, gt, gte, lt, lte, in, exists
  • Returns actions, an evidence count (never an invented percentage) and a trace
  • Counterfactuals: “what would change this decision?”

lib/governance

Versions, approvals, audit.

  • Semantic versions, JSON diff, append-only rollback
  • Three-person separation of duties, enforced — and each refusal audited
  • Role and sensitivity-based redaction, applied on the server before data reaches the browser

lib/llm · Tencent Cloud

Language work only. Never a decision.

  • Hunyuan hy4-preview via TokenHub — live on the public demo, dedicated Singapore endpoint (~3.9 s)
  • MiniMax Speech 2.8 HD via TokenHub — the voice on screen and the film’s narration
  • Hunyuan through the CodeBuddy Agent SDK locally; OpenAI then recorded output as fallbacks
  • The badge always names the provider that actually answered
Proven, not asserted

1,302 automated tests, including adversarial and property-based tests (fast-check) over the engine and the governance layer. Design mapped to the IMDA Model AI Governance Framework (2020 and the 2026 Agentic AI edition), AI Verify, ISO/IEC 42001 and the NIST AI RMF.

How prompts drive the AI generation

The model does language. It never decides a safety action.

1

Elicit

One wide question first — “walk me through the last time…” — because an unprompted account gives up more than ten narrow questions do.

  • Probes tagged against a 31-probe library from the Critical Decision Method and ACTA.
2

Extract

A schema-constrained “scribe” prompt maps speech into the rules.yaml schema.

  • Strict structured output, thinking disabled.
  • Output is always a DRAFT candidate the expert must confirm.
  • If no live model answers, it says so — it will not show a recorded reading of a different conversation.
3

Resolve

Two answers about the same field with different claims disagree.

  • In the exercise this is string comparison, not inference — the engine simply knows.
  • The conflict becomes one distinguishing condition; neither half is dropped.
4

Compose

Tenant notices are drafted under the Tenant Experience pill’s hard rules.

  • No cause before the cause is confirmed (TE-03); no completion time before isolation (TE-02); PII masked (TE-05).
  • Unsupported prose fails closed. A named human approves. Keystone never sends it.
The invariant

The decision path takes no model input. Change the model, change the wording — you cannot change whether the gate holds.

Rule drafting, contradiction resolution and notice drafting are all demonstrable in the live app7 / 8

What Keystone already measures, over the demo data

  • Replay agreement — “x of y assertions”, from the deterministic engine, never a made-up percentage.
  • Eval pass and shadow agreement per pill; decisions awaiting approval; pills approved; pending corrections.

The pilot would measure

  • Time to isolate · escalation latency · gate-block rate · override rate · eval agreement · rollback frequency.
  • Goal: a measurable cut in time to isolate and in unplanned re-energisation risk — and new engineers making guided decisions with named escalation from day one, instead of after months of shadowing.
