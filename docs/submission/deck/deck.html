The real-world problem

The judgement that keeps a building safe is in a few heads, and those heads are leaving.

1

Concentrated

Keppel’s own brief: critical knowledge sits with a few experts; new staff need a long time to build it.

  • One Chief Engineer, 18 years of M&E, holds the chilled-water leak playbook.
  • A wrong call means unsafe re-energisation.
2

Never written down

The useful part is tacit: when to break the rule, and why.

  • “Always isolate the riser” vs “isolate the sub-valve” — both true, under different conditions.
  • SOPs record the step, not the judgement.
3

Lost at retirement

Replacing an employee costs 0.5–2× annual salary (Gallup); FM talent growth “is not keeping pace” (JTC, 2025).

  • The knowledge leaves with the person.
4

AI can’t be trusted to act

A chatbot that answers from a manual will also answer when it shouldn’t.

  • Asked outside its pill, our published agent replies: “This is not covered by an approved pill.”

REIT managers and property/facility-management organisations running mixed portfolios — offices, data centres, logistics. We model the real chain: REIT manager → property/facility manager → FM contractor, with 15 named personas.

Flow 1 · the decision path

How a gate decides — and why a model cannot move it.

The evidence

Water reached DB-23A and the circuit is isolated — but no Licensed Electrical Worker has inspected it yet.

The rule fires

TS-07 triggers. lew_signoff is required, absent, and the rule forbids the action without it.

The outcome

Blocked. Escalated to the duty LEW by name. The AI’s proposal to re-energise AHU-23-01 is held, not executed.

Whatever the outcome, nothing executes

Every branch of this chart ends with a person. The engine is pure TypeScript with no model input, no eval() and no string expressions — so changing the model, or the prompt, cannot change which branch you land on.

The reusable unit

An Intelligence Pill is plain text the organisation owns.

What is in the package

pills/technical-services/chilled-water-leak/

SKILL.mdOwner, steward, approver, version, access and boundaries — plus the prose an LLM host reads.
rules.yaml13 rules: structured triggers, required evidence, action class, forbidden actions, escalation target, deadline, asset overrides.
evidence.yamlThe shared vocabulary — one contract both the pill and the app are tested against.
provenance.jsonEvery rule mapped to the expert’s quote, timestamp and confirmation.
evals/Six past incidents a new version must still agree with.
CHANGELOG.mdAppend-only history.

Why plain text matters

  • Portable. Copied unchanged into .codebuddy/skills/, CodeBuddy reached the same TS-07 decision as our engine — blocked, escalate to the duty LEW, quoting the Chief Engineer. Verified, not claimed.
  • Reviewable. A rule change is a diff an engineer can read.
  • Model-independent. The decision path takes no model input, so swapping the model cannot change a safety outcome.
  • Yours. It is a folder in your repository, not rows in a vendor’s database.

The gate, in one line

Status precedence is fixed code:

not applicable → blocked → escalate → needs approval → allowed

  • Evidence counts only when it is confirmed and exactly true.
  • An exception may add a requirement. It can never relax a gate.
  • No AI proposal ever executes. Each is held for a named human.

How prompts drive the AI generation

The model does language. It never decides a safety action.

1

Elicit

One wide question first — “walk me through the last time…” — because an unprompted account gives up more than ten narrow questions do.

  • Probes tagged against a 31-probe library from the Critical Decision Method and ACTA.
2

Extract

A schema-constrained “scribe” prompt maps speech into the rules.yaml schema.

  • Strict structured output, thinking disabled.
  • Output is always a DRAFT candidate the expert must confirm.
  • If no live model answers, it says so — it will not show a recorded reading of a different conversation.
3

Resolve

Two answers about the same field with different claims disagree.

  • In the exercise this is string comparison, not inference — the engine simply knows.
  • The conflict becomes one distinguishing condition; neither half is dropped.
4

Compose

Tenant notices are drafted under the Tenant Experience pill’s hard rules.

  • No cause before the cause is confirmed (TE-03); no completion time before isolation (TE-02); PII masked (TE-05).
  • Unsupported prose fails closed. A named human approves. Keystone never sends it.
The invariant

The decision path takes no model input. Change the model, change the wording — you cannot change whether the gate holds.

Rule drafting, contradiction resolution and notice drafting are all demonstrable in the live app9 / 12

Built and working

Features we would show you, not describe to you.

Teach any pill

A situation, one open question, then only what is still missing — and a board showing which fields of the rule are still unknown.

  • Questions for a pill nobody wrote any for are derived from that pill’s own rules, wrong answers included.

Hear where it came from

Every rule links to the second of the recorded call where it was said, and plays it.

  • Provenance is a quote, a timestamp and the name of whoever confirmed it.

Why? and what-if

Each decision opens a drawer: rule, pill version, evidence used, evidence missing, owner, escalation target.

  • Counterfactual: “what would change this decision?” is answered from the unmet conditions, not guessed.

Capture at the plant

A QR label on the equipment opens a capture task. Consent first; audio is not kept; credit is opt-in.

  • Read-back chips for numbers, times, tags and roles — found by regex and the registers, never by the LLM.

Replay before release

A new version is replayed against closed incidents and reported as “x of y assertions” — a count, never an invented percentage.

One pill, many assets

Asset overrides reroute the same rule: at a colocation data centre TS-07 escalates to the Critical Facilities Manager and the notice becomes a client-SLA notice.

Roles that actually bite

Fifteen personas. The page reads your role from a signed session and the server masks anything above your clearance before it reaches the browser.

Runs inside CodeBuddy

The pill installs unchanged as a native CodeBuddy skill and reaches the same TS-07 decision as our engine. Verified, with screenshots.

And what we deliberately did not build

The teach exercise previews a draft and stops there — choosing which existing rule a new statement amends is a judgement, so a person places it. Hand-written questions exist for one pill; the rest are generated. Versions and the audit log are browser-local in this demo. Speech recognition has not been tested on real Singapore-accented field speech, and we do not claim it.

What is novel

Five things here that a retrieval chatbot cannot do.

1

A gate, not a prompt

Safety lives in fixed code, not in instructions a model is asked to follow.

  • Exceptions can only add requirements — there is no path that relaxes a gate.
  • Prompt injection cannot reach the decision: it takes no model input at all.
2

Contradiction as arithmetic

Each answer carries a claim token about one field of a rule. Two different claims about one field disagree — by string comparison.

  • Nothing has to notice the conflict, so nothing can fail to.
  • Both statements are kept; the condition that separates them is named.
3

Knowledge that outlives the model

The pill is plain text with an owner, a version and tests — not weights, not an index.

  • The same file reached the same decision in CodeBuddy as in our engine.
  • Switch vendor and the judgement comes with you.
4

It refuses to invent

Asked outside its pill, the published agent says “this is not covered by an approved pill” rather than answering.

  • When no live model answers an extraction, it says so — it will not pass a recorded reading of another conversation off as a reading of yours.
5

Governance that executes

Separation of duties, eval gating, shadow mode, audit and rollback are code paths with tests, not a policy page.

  • The author cannot shadow it; the shadow promoter cannot approve it; refusals are audited.

What Keystone already measures, over the demo data

  • Time to isolate, read from the incident records.
  • Replay agreement — “x of y assertions”, from the deterministic engine, never a made-up percentage.
  • Eval pass and shadow agreement per pill; decisions awaiting approval; pills approved; pending corrections.
  • An illustrative downtime-avoided estimate, with its assumption stated on screen (4 hours per blocked re-energisation).

The pilot would measure

  • Time to isolate · escalation latency · gate-block rate · override rate · eval agreement · rollback frequency.
  • Goal: a measurable cut in time to isolate and in unplanned re-energisation risk — and new engineers making guided decisions with named escalation from day one, instead of after months of shadowing.
